This repository is classified as **security-sensitive** because:

- Parser code handles untrusted documents
- Malformed input can cause crashes or resource exhaustion
- FFI boundary requires careful memory safety
- Dependencies must remain GPL-free

See [agent-identity standard](https://crucible.3leaps.dev/repository/agent-identity) for modes and attribution.

## Project Overview

**docprims** is a GPL-free, cross-platform document text extraction library implemented in Rust with bindings for Go, TypeScript, and Python.

**Core differentiator**: Extract text from documents without GPL license contamination.

**Key principle**: Reliable text extraction from untrusted documents, safely embeddable in commercial software.

## Session Protocol

### Before Changes

- Read relevant code first
- Understand input validation implications
- Keep changes minimal and focused
- Consider malformed input handling

### Before Committing

- Run `cargo fmt && cargo clippy` (or `make check`)
- Run `cargo test`
- Run `cargo deny check licenses`
- Verify no unintended changes with `git diff`
- Use proper commit attribution (see below)

## Session Continuation

Agents may receive context from continuation prompts to maintain session continuity across context window boundaries.

### Continuation Prompt Location

This repository does not use committed continuation prompts. The `.plans/` directory
is always local-only (gitignored) and must never be committed.

If you need tactical session guidance, use `AGENTS.local.md` (gitignored) or coordinate
with the maintainer via the issue/PR description.

### Continuation Prompt Format

Continuation prompts should include a UTC timestamp at the top to help determine relevance:

```markdown
<!-- Generated: 2025-01-25T23:15:00Z -->

# Session Continuation: <rolename>

## Current Task
<description of active work>

## Context
<relevant background, decisions made, blockers encountered>

## Next Steps
<planned actions, pending items>

## Key Files Modified
<list of files touched in this session>
```

### Freshness Guidelines

- **< 1 hour old**: Treat as current session context
- **1-24 hours old**: Review but verify state before proceeding
- **> 24 hours old**: Treat as stale; confirm with maintainer before relying on it

## DO / DO NOT

### DO

- Run `cargo fmt && cargo clippy` before commits
- Read files before editing them
- Keep changes focused on the task
- Validate all input from documents
- Check for resource limits (memory, CPU)
- Reference decision records when making architectural choices
- Test with malformed input

### DO NOT

- Push without maintainer approval
- Skip quality gates or license checks
- Commit secrets or credentials
- Add GPL/LGPL/AGPL dependencies
- Touch code outside task scope without justification
- Trust document content implicitly
- Commit `.plans/` directory (gitignored)
- Commit `AGENTS.local.md` (gitignored)

## Critical Rules

### Never Push Without Approval

Git push operations require explicit, per-incident human maintainer approval:

```bash
git add <files>       # OK
git commit -m "..."   # OK
git push              # NEVER without explicit approval
```

### License Compliance

All dependencies must pass `cargo deny check`:

```bash
cargo deny check licenses    # Must pass
cargo deny check advisories  # Must pass
```

See [ADR-0001](docs/decisions/ADR-0001-license-policy.md) for allowed licenses.

### Parser Safety

All parser code must:

- Validate input before processing
- Limit resource consumption (memory, iterations)
- Handle malformed input gracefully
- Never trust document content
